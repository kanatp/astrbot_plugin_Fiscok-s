# 话题记忆（词向量检索）功能实现方案

## Context（背景与目标）

当前 Fiscok 插件存在一个延迟/成本问题：本体 AstrBot 对群聊按 `umo` 整群共享会话历史，历史消息随轮数持续累积，每次请求都携带完整上下文，导致请求体积增大、首字延迟升高（此前已确认这是延迟的主因之一）。

本次要新增一个 **持久化话题记忆** 能力：

- 用 **词向量** 记住特定话题，存储形式为 `唤起词：话题记忆（一段原始对话）`；
- **由模型自主决定**是否保存某个话题（后台辅助 LLM 判定，不阻塞主对话）；
- 增加 **记忆上下限**（上限=最大条数，下限=相似度阈值）以保证存储性能与注入质量；
- 读取时通过 **词向量相似度** 抽取话题库内容。

用户将自行把本体上下文改短、压缩得更狠（**插件不裁剪 `req.contexts`**），插件只负责在 `on_llm_request` 阶段把检索到的话题作为 **补充信息** 注入 `system_prompt`，从而在更短的上下文下仍保留关键长期信息，节约 token。

## 已确认的关键决策

1. **词向量来源**：复用 AstrBot 内置 `EmbeddingProvider`（最轻，零额外依赖）。通过 `context.get_all_embedding_providers()` / `context.get_provider_by_id(id)` 获取；未配置时该功能自动禁用，不影响其他功能。
2. **上下限语义**：上限 = 话题最大条数（超出按时间淘汰最旧）；下限 = 检索相似度阈值（低于阈值不注入）。
3. **上下文策略**：**不裁剪** `req.contexts`（用户自行处理本体上下文压缩），插件仅做话题检索与注入。
4. **保存触发**：后台辅助 LLM 判定（复用情绪分析范式：后台异步 + 关闭思考的独立 Provider）。

## 实现步骤

### 1. 配置项：`_conf_schema.json` 新增 `topic_memory_config` 分组

新增第 5 个配置分组（`type: object`，`default: false` 启用开关），字段：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `available` | bool | `false` | 是否启用话题记忆功能 |
| `embedding_provider_id` | string (`_special: select_provider`) | `""` | 用于词向量的 Embedding Provider；留空取第一个可用；无则功能禁用 |
| `llm_provider_id` | string (`_special: select_provider`) | `""` | 用于话题判定/抽取的 LLM Provider；留空取第一个可用；辅助调用自动关闭思考 |
| `max_topics` | int | `300` | 记忆上限（最大条数），超出按时间淘汰最旧 |
| `min_similarity` | float | `0.5` | 记忆下限（相似度阈值），低于该值的话题不注入 |
| `retrieve_top_k` | int | `3` | 单次检索最多注入的话题条数 |
| `analyze_probability` | float | `0.2` | 触发后台话题判定的概率，用于节流辅助 LLM 成本（对齐 meme 学习概率范式） |

### 2. 存储层：`core/api/storage_apis.py` 新增 `topic_memory` 分节

- 目录：`self.topic_memory_root = self.root / 'topic_memory'`，在 `create_folder()` 中创建（含旧目录兼容分支，与 `meme_library_root` 一致）。
- 文件：`topic_memory/topic_db.json`，结构为列表：

```json
[
  {
    "id": "topic_20261009_143000_123",
    "keyword": "唤起词",
    "content": "话题记忆（一段原始对话）",
    "vector": [0.01, -0.23, "..."],
    "timestamp": "2026-10-09T14:30:00"
  }
]
```

- 读取/写入使用 **紧凑 JSON**（`ensure_ascii=False, separators=(',', ':')`），避免向量数组占用大量空白、保证存储性能。
- 接口：
  - `_get_topic_db_path()` / `_load_topic_db()` / `_save_topic_db(db)`
  - `add_topic(keyword, content, vector) -> str`：追加条目；超过 `max_topics` 时按 `timestamp` 淘汰最旧。
  - `get_all_topics() -> List[Dict]`、`get_topic_count() -> int`、`clear_topics()`。
  - `_generate_topic_id()`（对齐 `_generate_meme_id`）。

### 3. 词向量与检索：新增 `core/api/topic_memory_apis.py`

- `resolve_embedding_provider(context, provider_id) -> EmbeddingProvider | None`
  - 优先 `context.get_provider_by_id(provider_id)`（需为 EmbeddingProvider）；否则 `context.get_all_embedding_providers()[0]`；都没有返回 `None`（功能静默禁用）。
- `async get_query_embedding(context, provider_id, text, timeout) -> list[float] | None`
  - 调用 `get_embedding(text)`，用 `asyncio.wait_for` 超时保护，失败返回 `None`。
- `async decide_topic_memory(context, llm_provider_id, nickname, dialogue) -> dict | None`
  - 复用 `get_aux_provider()`（关闭思考）调用辅助 LLM，返回 `{"keyword": ..., "content": ...}` 或 `None`（模型判定不需要保存）。沿用 `emotion_apis._extract_json` 的解析思路（可抽为本地 helper）。
- `_cosine(a, b) -> float`：纯 Python 余弦相似度（不引入 numpy）；维度不一致的条目跳过并记警告。
- `retrieve_topics(topics, query_vector, top_k, min_similarity) -> List[Dict]`
  - 对 `get_all_topics()` 逐条算相似度，过滤 `< min_similarity`，降序取 `top_k`。

### 4. 提示词：`core/prompts.py` 新增话题记忆段

- `TOPIC_MEMORY_ANALYSIS_SYSTEM_PROMPT`：说明这是为机器人维护长期话题记忆的判定器，只返回 JSON。
- `TOPIC_MEMORY_ANALYSIS_PROMPT`（formatted：`nickname`、`dialogue`）：要求返回
  ```json
  {"save": true/false, "keyword": "唤起词（简短，便于日后唤起）", "content": "话题记忆（忠实还原的原始对话片段/要点）"}
  ```
  并说明保存判定标准（值得长期记住、有明确话题、非一次性的寒暄）。
- `format_topic_memory_injection(topics: List[Dict]) -> str`：把检索到的话题拼成注入块，形如：

```
<相关话题记忆>
以下是你过去记住的相关话题，作为背景参考（无需复述来源）：
- 唤起词：<keyword>
  话题内容：<content>
</相关话题记忆>
```

### 5. 钩子接入：`main.py`

- 新增导入：`topic_memory_apis` 的相关函数、`format_topic_memory_injection`。
- **判定保存（后台异步）**：新增 `@filter.event_message_type(ALL) topic_learn_on_message(event)`：
  - 未启用 / 无 embedding provider → return；
  - 以 `analyze_probability` 概率节流；忽略引用/转发消息（对齐 meme 钩子）；
  - 同步取出 `nickname`、最近消息文本后交给 `_spawn_background`，避免 event 被回收；
  - 后台任务：`decide_topic_memory(...)` → 若返回话题，则 `get_embedding(content)` 计算向量 → `data_manager.add_topic(...)`；全程 try/except 降级。
- **检索注入（同步等待，带超时）**：新增 `@filter.on_llm_request() on_llm_request_topic_hook(event, req)`：
  - 未启用 → return；
  - `resolve_embedding_provider` 为 `None` → return；
  - 用最近一条用户消息 `event.message_str` 作为查询，`get_query_embedding` 拿向量（超时保护）；
  - `retrieve_topics(...)` 得结果，非空则 `req.system_prompt = f"{req.system_prompt or ''}\n{injection}"`；
  - 全程 try/except，任何失败都不影响主请求。
- **管理指令**：新增 `@filter.command_group('topic_memory_manager', alias={'话题记忆管理'})`：
  - `list`（列出最近若干条 `keyword`，不含向量）便于验证；
  - `clear`（清空话题库，ADMIN）；
  - `count`（当前条数 / 上限）。

> 注意：`terminate()` 无需额外清理（Embedding Provider 来自本体 `context`，非插件克隆，不应关闭）。

## 边界与降级

- 未配置 embedding provider / 未启用 → 功能静默关闭，不影响任何现有功能。
- 辅助 LLM 判定失败 / embedding 调用超时 → 跳过本次，不写入、不注入，不影响主请求。
- provider 更换导致向量维度不一致 → 检索时跳过维度不符的条目并记录警告（不崩溃）。
- 默认值全部为"关闭"或安全值，**不改变既有行为**（默认 `available=false`）。

## 验证方式（端到端）

1. 在 AstrBot 中配置一个 Embedding Provider（如 Ollama / 某 API），并在插件配置中启用 `topic_memory_config`（`available=true`，`embedding_provider_id` 留空或指定）。
2. 重启/重载插件，观察日志无异常。
3. 在群内围绕某话题（如"我最喜欢的游戏"）进行几轮对话，用 `话题记忆管理 list` 查看是否已记录 `唤起词`；用日志确认 `add_topic` 写入。
4. 隔一段时间/新会话中提一句与该话题相关的话，通过日志确认检索命中并注入 `system_prompt`（可临时打日志输出命中的 `keyword` 与相似度）。
5. 用 `话题记忆管理 count` 确认条数受 `max_topics` 约束（可临时调小上限，连续写入验证淘汰最旧）。
6. 关闭 `available` 后确认功能完全静默、其他功能（表情包/情绪/推特）不受影响。
